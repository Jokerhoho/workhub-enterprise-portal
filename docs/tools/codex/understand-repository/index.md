# 02 · 读懂陌生仓库

理解仓库的目标不是生成一份目录说明，而是回答：用户请求从哪里进入、经过哪些模块、数据在哪里变化、结果如何返回、修改时有哪些约束。

## 先只读，不修改

```text
请先只读分析这个仓库，不要修改文件、安装依赖或访问外部系统。

输出：
1. 项目用途、技术栈和启动入口；
2. 主要目录及职责；
3. 构建、测试、格式和部署方式；
4. 一个用户请求从入口到结果的关键调用链；
5. 权限、数据和外部依赖；
6. 仍不确定、需要我确认的问题。

每个重要结论指出对应文件，不要根据常见框架习惯猜测。
```

## 先找这些文件

- README、CONTRIBUTING 与架构说明；
- 项目级和子目录级 `AGENTS.md`；
- 包管理、构建和测试配置；
- 应用入口、路由与依赖注入；
- 数据模型、迁移与权限；
- CI/CD、容器和部署配置；
- 环境变量示例，不读取真实密钥。

## 追一条真实调用链

选择一个具体行为，例如“用户点击登录后发生什么”，要求按顺序列出：

| 层 | 需要回答 |
| --- | --- |
| UI / API 入口 | 请求从哪个文件进入 |
| 校验 | 输入和权限在哪里检查 |
| 业务逻辑 | 谁决定结果 |
| 数据层 | 读取或写入什么 |
| 外部服务 | 调用了什么依赖 |
| 返回与错误 | 成功和失败如何传回 |

只要有一环不确定，就明确标记，不要补齐“应该存在”的模块。

## 生成一份接手地图

```text
基于刚才的分析生成“接手地图”：
- 5 个最重要文件；
- 3 条关键调用链；
- 运行与测试命令；
- 修改高风险区域；
- 常见任务应该从哪里开始；
- 需要向原维护者确认的问题。
控制在两页以内，所有结论带文件路径。
```

## 用 AGENTS.md 固化项目规则

`AGENTS.md` 可以告诉 Codex 项目的工作方式，例如安装、测试、代码风格、允许修改范围和交付要求。规则要具体、可执行，避免“保持高质量”一类无法验证的表述。子目录可以有更具体的说明，离目标文件更近的规则用于覆盖更通用的规则。

## 验收

- 关键结论都有文件证据。
- 调用链按真实代码顺序，不是框架模板。
- 明确区分已确认和待确认。
- 没有读取敏感环境文件。
- 后续任务能根据接手地图快速定位文件。
