# 01 · 环境与首个任务

第一次使用 Codex，不要从“做一个完整系统”开始。选一个能在几分钟内检查结果的小任务，先跑通分析、修改、验证和审查的闭环。

## 选择使用界面

| 界面 | 适合场景 |
| --- | --- |
| Codex 桌面应用 | 管理多个项目、文件和长任务，查看多个聊天与工作区 |
| Codex CLI | 在终端中读写仓库、运行开发工具、做脚本和自动化 |
| IDE 扩展 | 编辑代码时就近提问和修改 |
| Codex Cloud | 在配置好的云环境中并行执行任务 |

团队应统一项目打开方式、允许的权限和最低验证要求，但不必强制所有人使用同一个界面。

## 第一次任务

打开一个测试仓库，先确认当前目录、分支和工作区状态，然后输入：

```text
请先阅读项目说明和相关文件。
目标：把首页按钮文案从“提交”改成“保存草稿”。
范围：只修改显示文案和对应测试，不改交互逻辑。
验收：
- 页面显示新文案；
- 相关测试通过；
- 没有无关文件变化。

请先说明可能涉及的文件，再完成修改和验证，最后汇总差异。
```

## 开始前的五项确认

1. **项目**：打开的是正确仓库和目录。
2. **状态**：知道当前分支和未提交改动属于谁。
3. **范围**：明确可以修改和不能修改的部分。
4. **权限**：知道文件、命令、网络和外部操作的授权边界。
5. **验证**：知道应该运行哪些测试、构建或人工检查。

## 看懂权限请求

Codex 可能在执行命令、访问网络或扩大写入范围前请求批准。不要只看按钮，要看它准备做什么、目标路径是什么、是否有更小范围的替代方案。来源不明脚本、删除操作、发布和生产环境动作需要更高审查等级。

## 第一次验收

- 差异只覆盖约定文件。
- 测试或构建结果明确。
- 没有修改密钥、环境配置或依赖。
- 没有推送、合并或发布。
- 最终说明包含改动、原因、验证和剩余风险。

## 常见问题

### Codex 修改得太多

把范围改成文件、模块或可观察行为，并明确“不要顺带重构”。

### 它找不到启动方式

先让它阅读 README、包管理脚本、测试配置和项目级 `AGENTS.md`，不要凭经验猜命令。

### 它说完成但没有证据

要求给出实际运行的检查、结果和仍未验证的部分；“看起来正确”不是验证。
