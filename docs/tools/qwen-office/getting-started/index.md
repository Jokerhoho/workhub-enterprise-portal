# 01 · 入口与首个任务

这一章只解决一件事：选对入口，跑通“创建任务 → 添加资料 → 多轮修改 → 检查成果 → 保存复用”的完整链路。

## 三个入口怎么选

| 入口 | 适合场景 | 注意事项 |
| --- | --- | --- |
| 网页端 | 临时使用、换设备、云端资料、快速交付 | 上传前确认资料是否允许进入云端 |
| 桌面端 | 高频文件处理、本地 Word/Excel/PPT、图片和视频 | 先明确允许读取和写入的目录 |
| 钉钉内 | 消息、文档、日程与团队协作中的即时任务 | 企业空间的能力受订阅与权限影响 |

不确定时先用网页端；需要直接处理大量本地文件时使用桌面端；工作入口本来就在钉钉时再使用钉内入口。

## 第一次任务：把会议记录变成行动清单

准备一份不含敏感信息的会议记录副本，然后新建任务并输入：

```text
请把附件整理为一份可继续编辑的会议纪要。

受众：项目组全员
必须包含：
1. 已确认决策；
2. 待办、负责人、截止时间；
3. 风险与依赖；
4. 待确认问题。

不能从原文确认的姓名、日期和结论统一标记“待确认”，不要猜测。
先给我内容预览，确认后再生成 Word。
```

## 完整操作链路

1. 登录后确认自己进入的是个人空间还是正确的企业空间。
2. 点击“新建任务”，一个独立目标建立一个任务。
3. 从本地或个人网盘添加材料。
4. 发送目标、输入、要求和交付形式。
5. 回答系统的澄清问题；同一目标的修改继续留在原任务。
6. 先检查预览，再生成或打开最终文件。
7. 核对内容后下载，或保存到个人网盘供后续任务复用。

## 在哪里找到成果

任务结束后通常会同时得到对话总结和一个或多个产物。网页端生成的文件会进入个人网盘的 Agent 工作区；Word、Excel、PowerPoint 可继续在线编辑，其他常见格式可预览或下载。不要只看对话里的总结，要打开真正交付的文件验收。

## 第一次验收

- 文件能够打开并继续编辑。
- 标题、结构和格式符合要求。
- 决策、建议、推测与待确认项没有混写。
- 负责人和截止时间能在原始记录中找到依据。
- 没有意外发送、发布或覆盖其他文件。

## 常见问题

### 任务一直在追问

通常是目标、材料或交付形式不完整。补充受众、时间范围、文件格式和必须包含的章节。

### 结果漂亮但不实用

把“用于什么决定”和“如何验收”补进去，不要只描述风格。

### 找不到文件

先在当前任务的产物区查找，再到个人网盘的 Agent 工作区确认；必要时让千问办公说明保存位置和文件名。
