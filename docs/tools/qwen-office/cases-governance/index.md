# 08 · 企业案例与治理

这一章把前面的能力组合成三个完整任务。每个案例都遵循同一条主线：材料盘点 → 事实底稿 → 结构确认 → 分步制作 → 交叉验收 → 人工发布。

## 案例一：月度经营复盘包

**输入：** 销售明细、预算表、上月报告、会议说明、品牌模板  
**交付：** 可刷新分析表、完整报告、8 页管理层 PPT

执行顺序：

1. 表格体检并确认指标口径。
2. 生成事实底稿和异常清单。
3. 业务负责人补充异常原因。
4. 形成“变化—驱动—影响—行动”的报告。
5. 将确认内容转为 PPT。
6. 交叉核对三份成果中的数字。

关键验收：所有图表都能追溯到底表；业务解释和数据事实分开；建议包含负责人和时间。

## 案例二：政策到执行清单

**输入：** 政策原文、公司现行制度、流程图、岗位清单  
**交付：** 差异报告、部门行动表、员工问答、培训 PPT

```text
先对政策原文和内部制度做条款级比对。
输出：新增要求、已满足要求、冲突项、待法务确认项。
不要直接改制度。
确认差异后，再按部门生成行动、负责人、截止时间和证据留存要求。
```

关键验收：每项行动能回溯到政策条款；法律判断标记为待专业人员确认；生效时间和适用对象准确。

## 案例三：活动项目工作台

**输入：** 活动目标、预算、日程、供应商材料、内容计划  
**交付：** 项目方案、预算表、进度网页、周报定时任务

先用文档与表格完成一次人工周报，确定字段和汇报方式；再创建内部项目网页；最后把信息收集与周报生成做成定时任务。不要让自动化直接修改预算或对外发布。

## 企业治理矩阵

| 场景 | 默认策略 | 必须人工确认 |
| --- | --- | --- |
| 普通公开资料 | 可用于测试 | 正式对外发布 |
| 内部资料 | 按数据分级处理 | 上传范围和共享对象 |
| 客户与员工数据 | 先脱敏、最小范围 | 使用授权与保存方式 |
| 连接器和 IM | 最小权限 | 外发、群可见性、账号写入 |
| 定时任务 | 先手工跑通 | 频率、失败通知、停用方式 |
| Pages | 先预览 | 域名、访问范围、表单和数据库 |

## 团队推广清单

- 选 3 个高频、低风险、结果可验收的任务。
- 为每个任务准备示例输入、模板、验收表和负责人。
- 记录账号版本、企业空间和可用能力差异。
- 每月抽查事实错误、权限越界和无效自动化。
- 把成功任务沉淀为模板或 Skill，不依赖个人聊天记录。
