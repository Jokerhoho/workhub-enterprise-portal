# 03 · 文档生产

高质量文档不是“一次生成”，而是先固定事实，再确认结构，最后写作和复核。这个顺序能显著减少遗漏、口径漂移和看似完整的错误内容。

## 标准工作流

```mermaid
flowchart LR
  A[材料盘点] --> B[事实底稿]
  B --> C[目录确认]
  C --> D[分章写作]
  D --> E[事实与格式复核]
  E --> F[生成可编辑文档]
```

## 第一步：建立事实底稿

```text
先不要写正式报告。请从附件中提取事实底稿，包含：
- 时间范围与版本；
- 关键数字及来源文件；
- 已确认事实；
- 材料之间的冲突；
- 缺失信息和待确认问题。
每条关键事实注明来源，不做材料之外的推断。
```

## 第二步：确认目录

告诉它读者和用途。同一批材料，面向管理层、执行团队和外部客户的结构完全不同。

```text
根据事实底稿设计一份面向管理层的报告目录。
主线是“发生了什么—为什么—影响—建议—需要决策”。
每章说明要回答的问题、使用的证据和预计篇幅。
先只输出目录，不写正文。
```

## 三类常用文档

### 会议纪要

- 决策、讨论意见、待办和待确认项分开。
- 每条待办包含负责人、截止时间、依赖与状态。
- 不从语气推测没有明确表达的结论。

### 项目方案

- 背景、目标、范围、方案、资源、里程碑、风险、验收完整。
- 把“建议”与“已经批准”明确区分。
- 关键选择附替代方案和取舍。

### 制度与操作手册

- 先确定适用对象、生效时间、角色和例外。
- 步骤使用可观察动作，避免“及时处理”一类模糊表达。
- 每项规则说明负责人、输入、输出和留痕方式。

## 文档改写模板

```text
请把这份初稿改成面向【受众】的正式文档。
保持事实、数字和结论不变，只调整：
1. 标题层级；
2. 重复内容；
3. 长句与术语；
4. 表格和列表的可读性。
不得新增材料之外的数据或案例。
输出修改说明和最终 Word。
```

## 验收

- 文档目的和读者在开头清楚可见。
- 每个关键结论有材料依据。
- 数字、时间和专有名词全文一致。
- 推测、建议、决定和待确认项有不同标记。
- Word 样式、目录、页眉页脚和表格能继续编辑。
