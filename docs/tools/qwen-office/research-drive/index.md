# 06 · 资料研究与网盘

资料研究的难点不是“总结”，而是知道用了哪些材料、哪些已经过期、哪些观点互相冲突，以及最终结论能否追溯。

## 先组织文件

建议在个人网盘建立：

```text
项目名称/
├── 00_说明与口径
├── 01_原始资料
├── 02_数据
├── 03_会议记录
├── 04_工作底稿
├── 05_最终交付
└── 99_待确认与归档
```

原始材料只追加不覆盖；阶段性底稿和最终成果使用日期或版本号命名。

## 建立来源登记表

| 字段 | 说明 |
| --- | --- |
| 来源名称 | 文件、网页或系统 |
| 发布者 | 谁提供 |
| 日期 | 发布时间或数据截止日 |
| 版本 | 文件版本或页面更新时间 |
| 用途 | 支持哪个问题 |
| 可信等级 | 一手、二手、待核实 |
| 限制 | 是否可以外发、引用或继续加工 |

## 研究任务模板

```text
请根据我添加的资料研究【问题】。
范围：【时间、地区、产品或人群】
优先级：官方与一手资料 > 公司内部确认材料 > 行业报告 > 其他文章。

先输出：
1. 来源登记表；
2. 材料之间的一致与冲突；
3. 已知事实、合理推断、待核实问题；
4. 建议的报告框架。

每个关键结论标注来源和日期。没有证据时明确说明，不要补写。
```

## 复用个人网盘

个人网盘中的文件可以在后续任务中再次添加，无需重复上传。Word、Excel、PowerPoint 可在线打开和编辑；千问办公生成的文件通常进入 Agent 工作区。团队应定期把最终版本移入明确的交付目录，避免工作区积累大量难以识别的中间稿。

## 研究结果的三层结构

1. **事实底稿**：只放来源明确的信息。
2. **分析说明**：说明推断逻辑和不确定性。
3. **决策稿**：根据受众提炼建议和待决定事项。

分层能避免修改决策稿时意外改变底层事实。

## 验收

- 来源、日期和版本完整。
- 过期资料已经标记。
- 事实、推断和建议分开。
- 冲突信息没有被静默合并。
- 最终文件与底稿保留关联。
