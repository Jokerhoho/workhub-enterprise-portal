# WorkBuddy 快速上手

WorkBuddy 适合处理跨文件、跨工具和多步骤的工作任务：读取允许访问的本地材料，调用 Skill 或连接器，把一次任务拆成可执行步骤，并将成功过程沉淀为团队可复用的工作流。

::: tip 适合从这里开始
第一次使用时，选择一个资料范围清楚、不会对外发送、结果容易检查的任务，例如整理一批本地文件、从材料生成会议行动清单，或把固定流程做成 Skill。
:::

## 适用场景

| 场景 | 可以交给 WorkBuddy 做什么 | 人工重点检查 |
| --- | --- | --- |
| 本地文件 | 分类、重命名、提取、汇总和生成新文件 | 路径、覆盖、删除与敏感信息 |
| 知识工作 | 汇总多份材料，形成报告、卡片或行动清单 | 来源、时效、事实与遗漏 |
| Skill / Agent | 固化方法，组合不同角色完成复杂任务 | 触发条件、权限和交接质量 |
| 连接器与自动化 | 连接企业工具，定时收集、处理和通知 | 授权范围、外部写入和失败回退 |

## 5 分钟完成第一个任务

1. 新建一个测试工作区，只放入允许处理的副本材料。
2. 说明目标、输入位置、输出格式、不能改动的文件和验收标准。
3. 让 WorkBuddy 先列计划与可能涉及的动作。
4. 确认计划后执行；删除、覆盖、联网、发送或修改外部系统前再次确认。
5. 对照原始材料验收结果，并记录有效指令。

## 可直接复制的任务模板

### 整理项目资料

```text
请整理当前工作区中的项目资料。
目标：建立“01_需求、02_方案、03_数据、04_交付、99_待确认”目录。
先只读扫描并输出文件清单、建议分类、重名和无法判断的文件，不要移动或删除。
我确认后再执行；保留原文件，输出一份变更记录。
```

### 从会议到跟进

```text
请根据会议记录输出：已确认决策、待办、负责人、截止时间、依赖、风险和待确认项。
没有明确负责人或日期时标记“待确认”，不要猜测。
先生成预览，不发送消息、不创建日程、不写入外部任务系统。
```

### 组织一个多 Agent 研究任务

```text
目标：【研究问题】
请先设计最多 3 个角色，说明每个角色的输入、产出、证据要求和交接方式。
统一要求：优先使用官方和一手来源；事实、推断和建议分开；记录来源日期。
先给计划和最终报告目录，确认后再执行。
```

## 验收清单

- 输入、输出与中间文件都位于约定范围。
- 删除、覆盖、外发、联网和外部写入动作已经单独确认。
- 结论可回溯到材料，无法确认的内容没有被补写成事实。
- 失败时能说明停在哪一步，已有结果可以保留或回退。
- 值得复用的流程已记录为模板、Skill 或案例。

## 安全边界

不要在测试任务中使用生产密钥、账号口令或未经授权的客户和员工数据。连接邮件、消息、文档、网盘、日程与业务系统时采用最小权限；自动化任务应设置失败通知、运行记录和人工暂停方式。
