# 案例：办公交付流水线

**适用对象：** 运营、项目、财务、管理团队  
**预计耗时：** 30–90 分钟  
**最终交付：** 分析表、正式报告、管理层 PPT、事实核对表

![从材料输入、计划、制作、检查到交付的六阶段流程](/images/skills/six-stage-workflow.webp)

## 先列出再安装

```bash
npx skills add anthropics/skills --list
```

这是 Anthropic 的官方示例技能仓库，但在其他 Agent 中使用仍需逐项检查兼容性、脚本、依赖与许可。也可以直接用 WorkBuddy 或千问办公的内置办公能力，不必为了同一任务重复安装。

## 输入材料

- 一份原始数据表
- 若干会议记录或业务说明
- 公司报告和 PPT 模板
- 数据口径、时间范围、受众与截止时间

## 任务一：形成事实底稿

```text
先不要写结论。检查数据表中的字段、单位、日期、空值、重复值和异常值。
输出“事实底稿”：指标定义、时间范围、数据质量问题、可确认事实、待确认问题。
保留原始数据，不覆盖源文件。
```

## 任务二：生成报告与汇报

```text
根据已确认的事实底稿生成：
1. 面向业务负责人的完整报告；
2. 面向管理层的 8 页 PPT；
3. 每个关键结论到原始数据或材料的对应关系。

要求：数字、单位、时间范围一致；无法确认的内容标记“待核实”；不要补写材料之外的事实。
```

## 任务三：交付前互检

```text
把报告、PPT 和事实底稿进行交叉核对。
检查所有关键数字、图表标题、单位、时间范围、来源和行动建议。
输出差异清单；只修复确认有误的内容，并保留修改记录。
```

## 验收矩阵

| 成果 | 必查项 | 负责人 |
| --- | --- | --- |
| 数据表 | 公式、单位、空值、重复值、统计口径 | 数据负责人 |
| 报告 | 事实、引用、结论与建议的边界 | 业务负责人 |
| PPT | 页数、结构、数字、品牌模板 | 汇报人 |
| 全套材料 | 三份成果中的数字与口径一致 | 项目负责人 |

## 工具选择

- **千问办公**：希望快速得到可继续编辑的文档、表格和 PPT。
- **WorkBuddy**：材料散落在本地文件或多个连接器，需要组织跨工具流程。
- **Codex + Skills**：成果生成涉及仓库模板、批量脚本、可版本化规则或自动验证。
