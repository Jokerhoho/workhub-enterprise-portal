# 案例：上线前的网站体验巡检

**适用对象：** 产品、设计、前端  
**预计耗时：** 20–40 分钟  
**最终交付：** 分级问题清单、证据、修复建议和复核结果

## 安装

```bash
npx skills add vercel-labs/agent-skills --skill web-design-guidelines -a codex
```

首次安装请先阅读[安全安装指南](/skills/getting-started/)，并在测试分支运行。

## 任务输入

- 本地项目或待检查页面地址
- 目标设备：桌面、平板、手机
- 关键任务：搜索、进入教程、复制命令、返回首页
- 品牌规范与不允许改动的区域

## 可直接复制的任务

```text
请使用 web-design-guidelines 对这个企业知识门户做上线前巡检，先只检查，不修改。

覆盖：
1. 键盘操作、焦点、标签与颜色对比；
2. 360px、768px、1440px 的响应式布局；
3. 搜索、筛选、复制安装命令的状态反馈；
4. 字体层级、卡片密度、导航一致性；
5. 加载失败、零结果和长文本边界。

每个问题给出：严重级别、页面位置、复现步骤、用户影响、最小修复建议。
最后给出“阻止上线 / 建议修复 / 可后续优化”三组结论。
```

## 预期结果

| 等级 | 示例 | 处理方式 |
| --- | --- | --- |
| 阻止上线 | 键盘无法操作核心入口、文字对比不足 | 发布前必须修复 |
| 建议修复 | 移动端筛选被截断、复制后无反馈 | 当前迭代完成 |
| 后续优化 | 卡片文案略长、动效可更克制 | 放入体验待办 |

## 复核提示

```text
根据已完成修改重新检查原问题。不要扩大检查范围。
对每项给出：已修复 / 部分修复 / 未修复，并附可重复的验证步骤。
```

## 案例验收

- 问题可复现，不只有主观评价。
- 严重级别与用户影响对应。
- 建议能落实到具体组件或样式。
- 修复后执行同一套复核任务。
